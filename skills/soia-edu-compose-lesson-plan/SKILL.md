# soia-edu-compose-lesson-plan

把已确认的课程大纲展开为逐课时可执行的教案与讲义结构，覆盖导入、讲解、练习、小结、互动、作业和延伸。保持教学目标、活动与评估一致，不虚构学习者隐私或课堂事实。

## 客户可读说明

### 这个技能可以做什么

| 客户想要 | 技能会做 | 客户能看到 |
|---|---|---|
| 把大纲变成可授课的教案 | 提取单课目标、内容与评估证据，编排课堂环节 | 逐课时流程、教师动作、学习者任务和时间分配 |
| 准备讲义框架 | 把核心概念、示例、练习和小结组织成讲义层级 | 可直接扩写的讲义目录与内容提示 |
| 增加互动和课后学习 | 设计与目标对齐的提问、协作、作业和延伸 | 互动规则、作业要求、评价标准与延伸资源方向 |

### 客户如何使用

1. 提供已确认的课程大纲，至少包含本课教学目标、受众起点、课时长度和评估方式。
2. 可选说明班级规模、授课方式、可用设备、材料限制和无障碍需求；只使用聚合描述。
3. 指定要生成一个课时还是整套课程，并说明需要详案、简案或讲义结构。
4. 审阅时间预算、互动可行性与作业负担，再提出调整。

### 依赖与安装

本技能是纯方法论技能，无强依赖、脚本或外部服务；无需配置即可完成教案和讲义结构。

```bash
claude plugin marketplace add soia-team/soia-open-skills
```

```bash
claude plugin install soia-edu-course@soia
```

只要这一个技能时，可用 npx 路线。注意技能会落进共享真源 `~/.agents/skills`；若同时装了插件，同一技能会出现两份索引且各自漂移，建议二选一：

```bash
npx skills add soia-team/soia-open-edu-course-skills -g -a '*' -s soia-edu-compose-lesson-plan -y
```

如需保存个人化授课偏好，只能放在用户自有的 schema v2 配置中：

```text
~/.config/soia-skills/soia-edu-compose-lesson-plan/config.yml
```

```yaml
schema_version: 2
defaults:
  lesson_minutes: 45
  plan_detail: detailed
  interaction_modes: [think_pair_share]
```

配置完全可选。若需要制作课件幻灯，可选用跨仓技能 `soia-dev-open-design-ops`；它缺失时仍交付完整教案和讲义结构，只省略幻灯制作步骤。

**WorkBuddy** 的装载单位是角色化专家而不是插件，`npx skills add -a '*'` 覆盖不到它，需要单独安装，见 [docs/install/workbuddy.md](https://github.com/soia-team/soia-open-skills/blob/main/docs/install/workbuddy.md)。

### 私密信息与中间数据

- 只接收完成教学设计所需的聚合信息，不索取真实姓名、学校、联系方式、成绩明细、健康状况或家庭情况。
- 个性化偏好只能进入上述用户私有配置；使用匿名代号、区间或群体特征，不把配置内容复制到公开示例或日志。
- 默认在对话中生成草案，不创建中间文件。客户要求保存时使用客户指定位置，并说明创建了哪些资源类别。
- 引用客户材料时只摘取必要内容；回执不暴露本地绝对路径、账户信息或可识别学习者数据。

### 日志与完成回执

完成时报告：处理的课时范围、每课时分钟核算、采用的互动与作业类型、目标对齐检查、显式假设和未解决问题。不得打印私有配置内容或逐个学习者信息。

## 输入契约

优先接收结构化大纲；至少需要：

```yaml
course_title: <课程名>
lesson:
  number: <课时序号>
  title: <课时标题>
  minutes: <正整数>
  objectives: [<可测量目标编号与文本>]
  key_points: []
  formative_assessment: <证据与判定方式>
audience:
  starting_level: <聚合描述>
delivery:
  mode: <线下|线上|混合>
  available_materials: []
```

若大纲缺少可测量目标或总时长，先请求补齐；无法等待时明确假设，并把结果标为待确认草案。不得根据模糊受众描述推断具体学习障碍、成绩或家庭背景。

## 工作流程

1. **校验大纲。** 检查单课目标是否可测、课时要点是否匹配目标、评估是否能提供达标证据；问题严重时先反馈，不盲目扩写。
2. **确定交付粒度。** 明确课时范围、详案或简案、是否需要讲义结构，以及授课方式和材料限制。
3. **分配时间。** 先预留小结与形成性检查，再按导入、讲解、练习分配剩余时间；所有环节分钟数之和必须等于课时长度。
4. **设计导入。** 用问题、情境或快速任务激活前置知识，并明确本课目标；不使用与目标无关的热闹活动。
5. **组织讲解。** 把内容拆成短讲解单元，每个单元配示例、检查理解的问题或可视化提示。
6. **安排练习与互动。** 从示范到引导练习再到独立迁移；写清分组方式、指令、产出、观察点、反馈方式和备选方案。
7. **设计小结与评估。** 让学习者产出可检查证据，回扣目标并说明判定标准，不用“是否听懂”作为唯一检查。
8. **布置作业与延伸。** 区分必做、选做和延伸，说明预计用时、提交物、评价标准以及与下一课的关系。
9. **构建讲义结构。** 按学习路径组织标题、关键概念、例子、练习区、易错点、小结和自检，不把教师操作说明混入学习者讲义。
10. **压力检查。** 重新计算分钟总和，检查材料可得性、互动规模、线上/线下适配、目标覆盖和认知负荷。
11. **交付与回执。** 给出教案、讲义结构、假设、替代方案和验证结果。

## 输出契约

### A. 课时教案

1. **课时信息**：课程、课次、主题、时长、授课方式、受众起点。
2. **本课目标与证据**：目标编号、达标表现、形成性评估。
3. **准备清单**：教师材料、学习者材料、空间或设备、无障碍替代方案。
4. **课堂流程表**：时间段、环节、教师动作、学习者任务、互动方式、材料、检查点与应变方案。
5. **小结与离堂证据**：回扣目标的问题或产出、判定方式、即时反馈。
6. **作业与延伸**：必做/选做、预计用时、提交物、标准、下一课衔接。
7. **课后复盘提示**：观察哪些证据、哪些内容需要重教；不得记录可识别学习者信息。

课堂流程必须明确包含导入、讲解、练习和小结。某环节不适用时，解释原因并把时间重新分配，不能静默省略。

### B. 讲义结构

1. 课题与学习目标。
2. 前置知识快速检查。
3. 核心概念与术语。
4. 分段讲解、示例与图示占位。
5. 课堂练习与记录区。
6. 易错点与纠正提示。
7. 本课小结与自检题。
8. 作业要求与延伸方向。

### C. 对齐与回执

附上“目标—课堂活动—学习证据”对齐表、分钟合计、显式假设、未覆盖项与下一步。若客户选择制作课件，只输出可交给 `soia-dev-open-design-ops` 的幻灯内容提纲；其安装和运行不是本技能完成教案的前提。

## 互动设计规则

- 每项互动写明目的、指令、时间、组织方式、预期产出和反馈方法。
- 按班级规模和授课方式提供可执行版本；信息不足时提供低技术门槛默认方案并标为假设。
- 为不愿公开发言或无法使用指定设备的学习者提供等价参与方式。
- 互动必须产出与教学目标相关的观察证据，避免只追求气氛。

## 质量门槛

- 每课时各环节分钟数之和严格等于课时长度。
- 每个目标至少对应一个课堂活动和一项可观察学习证据。
- 导入、讲解、练习、小结均有明确作用，互动指令可直接执行。
- 作业负担与受众和课时相称，包含预计用时及评价标准。
- 教案与学习者讲义的内容边界清楚，幻灯工具缺失不影响核心交付。
- 不含任何真实机构、学生或家庭信息。

## 虚构示例

输入：“根据示例课程《校园气象观察》的第 2 课大纲，编写 45 分钟教案和讲义结构，受众为零基础学习者。”

“示例课程”仅为虚构占位；不得补写真实学校、班级、教师、学生或家庭资料。
