# soia-edu-design-course-outline

把课程主题、受众特征和课时限制转化为目标可测、结构连贯、评估对齐的课程大纲。交付物覆盖教学目标、模块与课时、前置知识和评估设计，不替代软件需求设计或传播内容策划。

## 客户可读说明

### 这个技能可以做什么

| 客户想要 | 技能会做 | 客户能看到 |
|---|---|---|
| 从一个主题规划完整课程 | 澄清受众、总课时、单课时长度和教学情境 | 课程定位、约束摘要和待确认假设 |
| 把学习期待变成可验收目标 | 用可观察动作、完成条件和达标标准改写目标 | 可测量教学目标与目标—评估对齐表 |
| 安排模块和每课时内容 | 按先修关系和认知难度排序，控制课时负荷 | 模块划分、每课时要点、前置知识与评估方式 |

### 客户如何使用

1. 说明课程主题、目标受众、总课时、每课时长度和教学场景。
2. 可选提供已有材料、必须覆盖或排除的内容、评估限制和无障碍需求。
3. 若关键信息缺失，先回答最少量澄清问题；无法等待时，明确列出假设再生成草案。
4. 审阅目标、课时负荷和评估方式；指出要调整的优先级或约束即可迭代。

  accessibility_needs: []

配置完全可选。示例值是通用占位，不得把真实机构、学习者或家庭信息写入技能文件、提示示例或公开仓库。

### 私密信息与中间数据

- 只使用完成任务所需的最少受众特征；优先使用年龄段、基础水平、班级规模等聚合描述。
- 真实姓名、学校、联系方式、成绩明细、健康状况和家庭情况不得进入技能、日志或公开样例。
- 用户确需个性化时，把数据写入上述用户私有配置，并用匿名代号或区间值；交付前移除可识别信息。
- 默认只在对话中生成草案，不落盘。客户要求保存时，写入客户指定位置；临时副本完成后删除或按客户约定保留。

### 日志与完成回执

完成时报告：采用的输入与显式假设、模块数和课时数、目标与评估的对齐检查、仍需客户确认的缺口。不得打印私有配置内容或学习者明细。

## 适用边界

- 以学习者达成教学目标为核心的课程设计，归本技能。
- 软件功能、接口、验收条件或技术实施方案属于 dev 域；遇到此类请求停止扩写课程大纲并建议转交相应 dev 技能。
- 宣传主题、渠道、内容日历或传播转化属于 media 域；只有内容服务于教学目标和学习评估时才由本技能处理。
- 若请求同时跨域，先拆分教学部分与非教学部分，只交付本技能范围并标记交接项。

## 输入契约

至少取得以下信息；缺失项必须询问或标为假设：

```yaml
topic: <课程主题>
audience:
  level: <起点水平>
  age_band: <可选，使用区间>
constraints:
  total_lessons: <正整数>
  minutes_per_lesson: <正整数>
  delivery_mode: <线下|线上|混合>
required_content: []
excluded_content: []
assessment_constraints: []
```

不得猜测具体学习者的身份、能力诊断或隐私属性。主题过宽而课时不足时，先缩小范围，不用堆叠要点掩盖超载。

## 工作流程

1. **界定任务。** 判断是否以教学目标为导向；把 dev、media 或其他域内容列为范围外。
2. **归一化约束。** 汇总总教学分钟数、课时数、授课方式、必须覆盖内容和不可变限制；检查数字是否相互一致。
3. **描述学习起点。** 只使用用户提供的聚合信息，列出必要前置知识；区分“已知”“推断”“待确认”。
4. **编写教学目标。** 每项目标包含可观察动作、学习内容、完成条件和达标标准；避免“了解、熟悉、掌握”等无法直接测量的单独表述。
5. **划分模块。** 按前置关系、从具体到抽象或从示范到迁移排序；每个模块绑定至少一个教学目标。
6. **分配课时。** 为每课时写明标题、对应目标、核心要点、学习活动和形成性检查；把复习、练习、反馈纳入时间预算。
7. **设计评估。** 为每项目标选择可产生证据的形成性或总结性评估，并给出判定标准；不以参与次数代替学习成果。
8. **攻击草案。** 检查目标是否可测、内容是否超载、先修是否缺失、评估是否真正覆盖目标，并修正断裂处。
9. **交付与回执。** 输出大纲和对齐表，标明假设、取舍、未覆盖内容与下一步。

## 输出契约

按以下顺序交付 Markdown；客户指定其他格式时保持字段语义不变。

1. **课程概览**：课程名、主题、受众、总课时、单课时长度、授课方式。
2. **范围与假设**：包含项、排除项、已知约束、待确认假设、跨域交接项。
3. **前置知识**：必需项、建议项和可选补救方式。
4. **可测量教学目标**：编号、动作、条件、达标标准。
5. **模块结构**：模块名称、模块成果、覆盖目标、课时范围。
6. **逐课时安排**：课时、对应目标、要点、活动、形成性检查、课后衔接。
7. **评估方案**：评估名称、证据形式、对应目标、评分或通过标准、反馈时点。
8. **目标—教学—评估对齐表**：每项目标至少对应一次教学活动和一项评估证据。
9. **质量检查与下一步**：时间核算、覆盖缺口、风险和需要客户确认的事项。

## 质量门槛

- 所有教学目标都能观察并判定是否达成。
- 模块与课时总数严格等于输入约束，时间预算不超额。
- 每课时要点数量与时长相称，并留有练习或反馈时间。
- 每项评估都能追溯到教学目标；每项目标都有教学活动与评估证据。
- 前置知识早于依赖它的内容出现，范围外事项没有混入交付物。
- 不含任何真实机构、学生或家庭信息。

## 虚构示例

输入：“为示例学校设计一门 6 课时的《校园气象观察》入门课程，每课时 45 分钟，受众为零基础学习者。”

只把“示例学校”视为虚构占位；输出仍应使用聚合受众描述，不补写校名、班级、学生姓名或个人画像。
